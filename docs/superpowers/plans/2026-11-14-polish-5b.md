# Measurement Set and Auto Shutdown (Sub-project 5b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Twelve measurements shown in three user-selectable bottom-bar slots, and an auto-shutdown timer, both saved with the settings.

**Architecture:** `fw/core/measure.[ch]` computes everything from the record and exposes one accessor per measurement kind (host-tested). `control` and `settings` carry the slot selections and the auto-off choice. `lcd` gains an 8x8 text routine; `ui` redraws the bottom bar as two half-height lines; `main` runs the idle timer.

**Tech Stack:** arm-none-eabi-gcc (no libm), host `cc` tests.

**Spec:** `docs/superpowers/specs/2026-11-13-dso510-firmware-design.md` § "Sub-project 5b: measurement set and auto shutdown".

## Global Constraints

- Never write or erase internal flash below 0x08007000. Never touch 0x08006000. SPI flash only through FatFs.
- Every app implements power-off.
- `fw/core/*`: no hardware header, host `cc -std=c99 -Wall -Wextra -Werror`, no libm (no `sqrtf`: write the square root by hand).
- `make -C fw clean everything 2>&1 | grep -ciE "warning|error"` prints `0`; `make -C tests` ends `… 0 failed`; `python3 -m unittest discover -s tools/tests` ends `OK`; bss of `fw/build/app.elf` below 73728.
- Measurement kinds, in this order (indices are stored in the settings file): frequency, period, duty +, duty −, width +, width −, maximum, minimum, peak-to-peak, amplitude, RMS, average.
- Slot defaults: frequency, duty +, peak-to-peak. Auto-off choices: Off, 5, 10, 30 minutes; default 10.
- Settings file: version 2, 160 bytes; version 1 (156 bytes) still read.
- Scope capture, generator, CSV save, USB drive, streaming and logger keep working unchanged apart from what the tasks specify.
- Subagents never flash and never open serial or USB devices.
- Commit after every task with targeted `git add` (never `-A`, never `.superpowers/`). Every commit message ends with the line `Claude-Session: https://claude.ai/code/session_01PdqjwHELxySe7PGVKMZmHp`.

### Task 1: Measurement core

**Files:** Modify `fw/core/measure.h`, `fw/core/measure.c`, `tests/test_measure.c`.

**Interfaces — produces:**
```c
enum { MEAS_FREQ = 0, MEAS_PERIOD, MEAS_DUTY_P, MEAS_DUTY_N, MEAS_WIDTH_P, MEAS_WIDTH_N,
       MEAS_MAX, MEAS_MIN, MEAS_VPP, MEAS_AMPL, MEAS_RMS, MEAS_AVG, MEAS_NUM };
enum { MEAS_U_HZ = 0, MEAS_U_S, MEAS_U_PCT, MEAS_U_V };
/* meas_t keeps valid, freq_hz, duty_pct, vpp_codes, vmin, vmax and gains (all in ADC codes): */
    float max_codes, min_codes;      /* extremes of the record (float so they can be averaged) */
    float top_codes, base_codes;     /* most frequent code at/above and below the mid level */
    float mean_codes, meansq_codes;  /* mean and mean square of the code over the statistics window */
/* Value of one measurement in its unit. volts_per_code and zero_code (the ADC code of 0 V, may be fractional)
   convert codes to volts. Returns 1 and sets *value and *unit, or 0 if it is not available (time measurements
   without a full period; unknown kind). *unit is always set for a known kind. */
int meas_value(const meas_t *m, int kind, float volts_per_code, float zero_code, float *value, int *unit);
const char *meas_name(int kind);   /* "Frequency", "Period", "Duty +", "Duty -", "Width +", "Width -", "Maximum", "Minimum", "Peak-peak", "Amplitude", "RMS", "Average"; "?" if unknown */
const char *meas_tag(int kind);    /* "Freq", "Per", "Duty+", "Duty-", "Wid+", "Wid-", "Max", "Min", "Vpp", "Ampl", "RMS", "Avg"; "?" */
```
`meas_avg_t` / `meas_avg_update` average the six new float fields the same way as the existing three (same restart rule, which still looks only at frequency and Vpp).

Definitions:
- Statistics window: samples `[first, last)` between the first and last rising crossing when `valid`, else the whole record. `mean_codes`, `meansq_codes`, and the histogram for top/base are taken over that window.
- `top_codes`: the most frequent code among samples ≥ mid level (`(min + max) / 2`); `base_codes`: the most frequent among samples below it; ties go to the code farther from the mid level. If the record is flat (`max − min < 8`), top = base = mean.
- `meas_value`: FREQ = `freq_hz`; PERIOD = `1 / freq_hz`; DUTY_P = `duty_pct`; DUTY_N = `100 − duty_pct`; WIDTH_P = `duty_pct / 100 / freq_hz`; WIDTH_N likewise with the negative duty; these six need `valid`. MAX = `(max_codes − zero) × vpc`; MIN likewise; VPP = `vpp_codes × vpc`; AMPL = `(top − base) × vpc`; AVG = `(mean − zero) × vpc`; RMS = `vpc × sqrt(meansq − 2·zero·mean + zero²)` (clamp the radicand at 0). Voltage kinds are always available.
- Square root: a static helper (Newton iterations from a sane start, exact 0 for 0) accurate to 1e-4 relative.

### Task 2: State, menu rows, settings version 2

**Files:** Modify `fw/core/control.h`, `fw/core/control.c`, `fw/core/settings.h`, `fw/core/settings.c`, `tests/test_control.c`, `tests/test_settings.c`, `fw/app/ui.c` (minimal, so the firmware stays consistent), `fw/app/main.c` (the settings load call only).

**Interfaces — consumes** `MEAS_NUM`, `MEAS_FREQ`, `MEAS_DUTY_P`, `MEAS_VPP` (Task 1). **Produces:**
- `scope_state_t.meas_sel[3]` (`uint8_t`, kinds; defaults `MEAS_FREQ, MEAS_DUTY_P, MEAS_VPP`) and `scope_state_t.auto_off` (`uint8_t` index into `auto_off_min`, default 2).
- `#define AUTO_OFF_NUM 4` and `extern const uint8_t auto_off_min[AUTO_OFF_NUM];` = `{0, 5, 10, 30}` (in `control.[ch]`).
- `MENU_ITEMS 9`: rows 0..4 unchanged (4 = Generator), 5..7 = `Meas 1..3`, 8 = `Auto off`.
- `CHG_MEAS 0x4000u`: the measurement line needs a redraw.
- `SETTINGS_LEN 160u`, `SETTINGS_LEN_V1 156u`, `SETTINGS_VERSION 2`.

Rules:
- Menu rows 5..7: a wheel tap steps `meas_sel[i]` through `MEAS_NUM` with wrap; returns `CHG_MENU | CHG_MEAS`. Row 8: a wheel tap steps `auto_off` through `AUTO_OFF_NUM` with wrap; returns `CHG_MENU`. The wheel press on these rows closes the menu as on rows 0..3. Up/Down wrap over 9 rows.
- Settings layout: bytes 0..153 as version 1; `154..156` = `meas_sel[0..2]`; `157` = `auto_off`; CRC over bytes 0..157 at `158`. `settings_pack` writes version 2. `settings_unpack` accepts `len == 160` with version 2, and `len == 156` with version 1 (CRC over 0..153 at 154; `meas_sel` and `auto_off` are then left untouched in `*s`). Any other length/version combination is rejected. Clamping: `meas_sel[i] >= MEAS_NUM` → that slot's default; `auto_off >= AUTO_OFF_NUM` → 2.
