# Settings Persistence and Parked Fixes (Sub-project 5a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scope and generator settings and the auto-zero result survive a power cycle; the generator's DC level is separate from the wave offset; timebase changes across calibration sets settle properly.

**Architecture:** Pure pack/unpack with validation in `fw/core/settings.[ch]` (host-tested). A tiny FatFs wrapper `fw/storage/cfgfile.[ch]` reads and writes one file (host-tested on the fake flash). The scope app loads at boot before USB starts and saves at power-off when something changed.

**Tech Stack:** arm-none-eabi-gcc (no libm), FatFs R0.15a (vendored), host `cc` tests.

**Spec:** `docs/superpowers/specs/2026-11-13-dso510-firmware-design.md` § "Sub-project 5a: settings persistence and parked fixes".

## Global Constraints

- Never write or erase internal flash below 0x08007000. Never touch 0x08006000. SPI flash writes only inside `[0, 0x500000)` — i.e. only through FatFs on the user volume.
- Every app implements power-off. Power-off must still complete if the settings write fails.
- `fw/core/*`: no hardware header, host `cc -std=c99 -Wall -Wextra -Werror`, no libm.
- `make -C fw clean everything 2>&1 | grep -ciE "warning|error"` prints `0`; `make -C tests` ends `… 0 failed`; `python3 -m unittest discover -s tools/tests` ends `OK`; bss of `fw/build/app.elf` below 73728.
- Settings file: `/DSO510.CFG`, exactly `SETTINGS_LEN` bytes, little endian, layout as in Task 2. Written only at power-off, only when changed, never while a capture save is in progress.
- Scope, generator, CSV save, USB drive, streaming and logger keep working unchanged apart from what the tasks specify.
- Subagents never flash and never open serial or USB devices.
- Commit after every task with targeted `git add` (never `-A`, never `.superpowers/`). Every commit message ends with the line `Claude-Session: https://claude.ai/code/session_01PdqjwHELxySe7PGVKMZmHp`.

### Task 2: `settings` core — pack, unpack, validate

**Files:**
- Create: `fw/core/settings.h`, `fw/core/settings.c`, `tests/test_settings.c`
- Modify: `tests/main.c`

**Interfaces:**
- Consumes: `scope_state_t` (`control.h`), `gen_cfg_t` incl. `dc_dv` (Task 1), `cal_t` (`cal.h`), `sp_crc16` (`stream_proto.h`), `tdiv_ns`, `vdiv_mv`, `NUM_TDIV`, `NUM_VDIV`, `gen_clamp`.
- Produces:
```c
#define SETTINGS_LEN 156u
/* Serialise the persistent settings into out[SETTINGS_LEN]. zeroed != 0: cal's lo/hi tables are stored as the auto-zero result. */
void settings_pack(uint8_t *out, const scope_state_t *s, const cal_t *cal, int zeroed);
/* Parse a settings file. Returns 1 and updates *s (persistent fields only), and, if the file carries a
   valid auto-zero result, cal->lo/hi and *zeroed = 1. Returns 0 and changes nothing if the file is not
   acceptable (length, magic, version, CRC, or a timebase / V/div value that is not in the tables). */
int settings_unpack(const uint8_t *in, uint32_t len, scope_state_t *s, cal_t *cal, int *zeroed);
```
Layout (offset: field), all little endian:
`0`: magic bytes `'D','S','S','1'` · `4`: version u8 = 1 · `5`: flags u8 (bit 0 = zeroed) · `6`: timebase ns u32 · `10`: V/div mV u16 · `12`: offset i16 · `14`: trig_level i16 · `16`: trig_pos i16 · `18`: trig_mode · `19`: edge · `20`: coupling_dc · `21`: probe_x10 · `22`: ctl · `23`: gen.on · `24`: gen.wave · `25`: gen.fine · `26`: gen.duty_pct · `27`: gen.amp_dv · `28`: gen.offset_dv · `29`: gen.dc_dv · `30`: gen.freq_hz u32 · `34`: `lo[3][10]` u16 (set-major: set 0 ranges 0..9, set 1, set 2) · `94`: `hi[3][10]` u16 · `154`: CRC-16 u16.

CRC-16 (`sp_crc16(0xFFFF, in, 154)`) stored at offset 154, low byte first.

Validation in `settings_unpack`, in this order: `len == SETTINGS_LEN`; magic; version == 1; CRC; timebase ns found in `tdiv_ns` and V/div mV found in `vdiv_mv` (else return 0). Then clamp: offset −100..100; trig_level 0..255; trig_pos 0..`PLOT_COLS − 1`; trig_mode 0..2 (out of range → 0); edge, coupling_dc, probe_x10, gen.on, gen.fine → 0/1; ctl < `CTL_NUM` else 0; generator fields through `gen_clamp`. Auto-zero tables: accepted only if flag bit 0 is set and all 60 words are ≤ `CAL_PWM_MAX`; otherwise `cal` and `*zeroed` are left untouched (the rest of the file is still used). Fields of `*s` that are not persistent (`run`, `menu_open`, `menu_item`, `gen_open`, `gen_item`) are never written.

```c
/* Store the settings if they changed. Only from power_down(), after the USB detach. */
static void settings_store(void) {
    static uint8_t b[SETTINGS_LEN];
    if (fs_busy) return;                         /* power-off in the middle of a capture save */
    settings_pack(b, &st, &cal, zeroed);
    if (cfg_have && !memcmp(b, cfg_saved, SETTINGS_LEN)) return;
    cfgfile_save(b, SETTINGS_LEN);               /* best effort: power-off continues either way */
}
```

Confirm by reading that `apply_time()` does call `apply_fe()`; if it does not, report instead of restructuring.
